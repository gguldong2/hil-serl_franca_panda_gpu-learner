RunPod 실행 절차

RunPod pod 를 만들고, 설치하고, 지금 서버에서 하듯 tmux 안에서 learner · actor · 대시보드를 띄우고, 멈추고 다시 켜는 순서다. 옆에 물어볼 사람(Claude 포함)이 없다고 보고, 칠 명령 · 나와야 하는 결과 · 막혔을 때 할 일을 모두 적었다.

00시작 전에

이 문서가 맞으려면
  • 저장소가 최신이어야 한다. 2026-11-08 에 스크립트 세 개를 RunPod 에 맞게 고쳤다: 01_install_system.sh(tmux · xdotool · gcc 추가), preflight.sh(Xvfb 자동 시작 · 다시 켠 pod 알아보기), train.sh. clone 한 뒤 04 의 확인 줄로 본다.
  • Panda 기준이다. 시연(data/panda_place_cube_demo, 43판 · 19,612 프레임)과 참고 정책(outputs/releases/)은 저장소에 들어 있어 clone 만 하면 된다. UR5e 시연은 저장소에 없다.
  • 숫자 옆 추정 은 RunPod 에서 아직 재 보지 않은 값이다. 재면 04 핸드북 §12 에 적는다.

ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519     # 없으면 만든다. 묻는 것은 엔터로 넘겨도 된다

RunPod 웹 → 계정 Settings → SSH Public Keys 칸에 그 한 줄을 붙여 넣고 저장한다. pod 를 만들기 전에 해 둔다 — 키는 pod 가 만들어질 때 들어간다.

순서대로

버튼 이름은 RunPod 화면이 바뀌면 조금 다를 수 있다 추정. 칸의 뜻은 위 표와 같다.

  1. Pods → + Deploy. 맨 위에서 Secure Cloud 를 고른다.
  2. GPU 를 고른다 — 목록에서 L40S(또는 RTX A6000), GPU Count 1. RTX 5090 · RTX PRO 6000 같은 Blackwell 이면 Additional filters → CUDA Version 을 12.8 이상으로(템플릿을 CUDA 12.8 로 고르면 저절로 맞는다).
  3. 템플릿 — Change Template → 공식 Runpod PyTorch. 버전을 고르는 칸이 있으면 CUDA 12.8 · Ubuntu 22.04, PyTorch 는 기본값. 이미지 이름이 runpod/pytorch:…-cu1281-torch…-ubuntu2204 꼴이면 맞다. 이 이미지 이름을 적어 둔다(04 T18). 이름이 "Ubuntu" 뿐인 템플릿은 JupyterLab 이 없을 수 있어 고르지 않는다.
  4. Edit Template(이 pod 에만 적용)을 눌러:
    • Container Disk 30 GB · Volume Disk 100 GB · Volume Mount Path /workspace
    • Expose HTTP Ports 는 8888 그대로 · Expose TCP Ports 에 22 가 있는지
    • Environment Variables 에 NVIDIA_DRIVER_CAPABILITIES = all, JUPYTER_PASSWORD = 긴 비밀번호 추가
    • Set Overrides(저장)
  5. Pricing 은 On-Demand. "Start Jupyter Notebook" 같은 체크박스가 보이면 켠다 추정.
  6. Deploy On-Demand → 상태가 Running 이 될 때까지 기다린다(이미지를 받느라 몇 분).
  7. Connect 탭에서 두 가지를 확인한다: ① "SSH over exposed TCP" 명령(ssh root@IP -p 포트 …) — 이것을 03 에서 쓴다. ② HTTP Services 의 Jupyter Lab 링크 — 웹에서 파일 보기(03). ①이 없으면 그 서버에 공개 IP 가 없는 것이다 — pod 를 지우고 다른 서버로 다시 만든다 추정.

템플릿 · CUDA 를 이렇게 고르는 이유

  • 템플릿의 PyTorch · CUDA 는 쓰지 않는다. 02 가 /workspace 의 프로젝트 venv 에 CUDA 런타임이 든 torch 2.11.0 을 따로 깐다. RunPod PyTorch 이미지에는 2.11 이 없고, 시스템에 깐 것은 pod 를 멈추면 지워진다(04 §07).
  • 템플릿의 CUDA 버전은 "그 버전을 지원하는 드라이버의 서버에만 뜬다" 는 조건으로만 작용한다. 12.8 이면 드라이버 570 이상 → cu126 · cu128 둘 다 된다. 12.9 · 13.x 도 되지만 고를 수 있는 서버가 좁아질 뿐 얻는 것이 없다 추정.
  • Ubuntu 22.04 는 기준 서버와 같다. 24.04 도 01 이 맞춰 두었지만 전체 설치는 아직 돌려 보지 않았다(04 §06).
만든 뒤 설정을 바꾸면

Edit Pod 로 환경변수 · 디스크를 바꿔 저장하면 pod 가 다시 시작되고 /workspace 밖이 지워진다. 그 뒤에는 12 다시 켤 때와 같다.

GPU 고르는 근거

GPU pod 를 고른다. CPU pod 는 GPU 가 없어 learner 와 카메라 렌더가 CPU 로 돌아 학습이 안 된다. vCPU · RAM 은 GPU 종류에 딸려 오므로 따로 고르지 않는다 — 아래 표에서 같이 본다.

  • 가격 · vCPU · RAM 은 runpod.io/pricing 의 2026-11-15 공시값이다. 자주 바뀌니 Deploy 화면의 값을 본다.
  • "RTX 6000" 은 이름이 셋이다 — RTX 6000 Ada(48 GB) · RTX PRO 6000(96 GB, Blackwell) · RTX A6000(48 GB, Ampere).
  • 세대는 고를 필요가 없다. 02 가 Ampere · Ada 는 cu126, Blackwell 은 cu128 을 알아서 고른다.
  • Community 가 싸지만 공개 IP 가 없는 서버가 섞여 있을 수 있다 — 위 순서 7번에서 "SSH over exposed TCP" 가 보이는지로 확인한다.
  • VRAM 계산: 약 7 GiB + (온라인 + 오프라인 칸 수) × 384 KiB + actor 0.65 GiB. 근거는 04 핸드북 §03.

03SSH 접속

내 PC — Connect 탭의 "SSH over exposed TCP" 명령에 -L 8088:localhost:8088 만 붙인다
ssh -L 8088:localhost:8088 root@<POD_IP> -p <SSH_PORT> -i ~/.ssh/id_ed25519
  • -L 8088:localhost:8088 은 대시보드 터널이다. 이 SSH 창이 열려 있는 동안 내 PC 브라우저의 http://localhost:8088/ 이 pod 의 대시보드로 이어진다.
  • "SSH" 칸의 …@ssh.runpod.io 명령(기본 SSH)은 쓰지 않는다. 그쪽은 파일 전송(scp)이 안 되고 터널도 기대할 수 없다.
  • 처음 접속하면 Are you sure you want to continue connecting 에 yes.
pod 안 — 받은 서버 확인 (출력은 적어 둔다)
nvidia-smi                          # GPU 이름 · 메모리 · Driver Version
df -h /workspace                    # 볼륨 크기 (100G 근처)
grep PRETTY_NAME /etc/os-release    # Ubuntu 22.04 또는 24.04
nproc                               # vCPU 수 — 체크포인트 저장 시간에 영향

브라우저로 파일 보기 · 고치기 — JupyterLab

VS Code 없이 웹에서 파일을 보고 고친다. 공식 PyTorch 템플릿에 JupyterLab 이 들어 있어 따로 깔 것이 없다.

  1. pod 의 Connect → HTTP Services → Jupyter Lab(포트 8888). 비밀번호는 JUPYTER_PASSWORD 에 넣은 값. 처음 켤 때는 1분쯤 걸린다 — 빈 화면이면 기다렸다 새로 고침.
  2. 왼쪽 파일 탐색기에서 /workspace/hil-serl-mujoco-franka 로 간다.
  3. .py · .json · .sh 는 두 번 누르면 편집기로 열린다(Ctrl+S 저장). docs/*.html 문서는 그대로 그려져 보인다(복사 버튼까지 쓰려면 위의 "Trust HTML"). .md 는 오른쪽 클릭 → Open With → Markdown Preview.
  4. File → New → Terminal 로 pod 셸도 열린다. 여기서 tmux attach -t hil 하면 SSH 창과 같은 learner · actor 창이 보인다.
  • /workspace 안에서 고친 것만 pod 를 멈춰도 남는다.
  • 대시보드(8088)는 여기서 열지 않는다 — 그대로 SSH 터널(-L 8088)로 본다.
  • VS Code 모양 그대로가 필요하면 브라우저용 VS Code(code-server)를 /workspace 에 깔아 SSH 터널로 여는 방법도 있다 실측 대기: curl -fsSL https://code-server.dev/install.sh | sh -s -- --method=standalone --prefix=/workspace/.code-server 뒤 tmux 새 창에서 /workspace/.code-server/bin/code-server --bind-addr 127.0.0.1:8443 --auth none /workspace/hil-serl-mujoco-franka, 내 PC 의 SSH 에 -L 8443:localhost:8443 을 더 붙이고 http://localhost:8443/. pod 안 127.0.0.1 에만 열리므로 SSH 터널로만 들어온다.

12다시 켤 때 (Start)

RunPod 화면에서 Start 한 뒤, Connect 탭에서 SSH 명령을 다시 복사한다 — IP · 포트가 바뀌었을 수 있다 추정.

다시 켜는 것은 스냅샷 복원이 아니라 템플릿 이미지로 컨테이너를 새로 만드는 것이다. Restart 버튼 · Edit Pod 저장 뒤에도 똑같이 이 절차를 따른다(/workspace 밖이 지워진다). 버튼별 차이는 04 핸드북 §09.

① 접속 · 환경 복구 (1~5분)
ssh -L 8088:localhost:8088 root@<POD_IP> -p <SSH_PORT> -i ~/.ssh/id_ed25519
cd /workspace/hil-serl-mujoco-franka
bash scripts/preflight.sh --fix        # 마지막 줄 "준비됨"

pod 를 멈추면 apt 로 깐 것과 Python 3.12 가 지워져 venv 가 깨진다. preflight --fix 가 이것을 알아보고([막힘] venv Python 안 돎 · 시스템 패키지 없음) 01_install_system.sh 를 다시 돌린 뒤, Xvfb 를 띄우고, 드라이버가 바뀌었으면 그래픽 라이브러리도 다시 받는다.

② 05 의 세션 블록을 그대로 다시 친다.

③ learner 창 bash scripts/train.sh learner → 체크포인트를 찾았다 -> 이어서 학습한다 · Resuming from step … 가 보이면, actor 창 bash scripts/train.sh actor → dash 창 bash scripts/dashboard.sh.

재개할 때 알아 둘 것

재개하면 버퍼 일부가 사라지고, 재시작 직후 몇 분간 성공률이 떨어지는 구간이 있다(03 §08 · 런북 §08). 고장이 아니다.

다시 켰는데 GPU 가 0 개

멈춘 pod 는 원래 서버에 묶여 있어서, 그사이 다른 사람이 그 GPU 를 빌렸으면 GPU 없이 켜진다(nvidia-smi 가 실패). 기다렸다 다시 켜거나, GPU 없이 켜서 결과를 내려받고 새 pod 를 만든다(04 핸드북 §09).

체크포인트는 2,000 스텝마다 81 MB 씩 쌓인다(하루 돌리면 7~20 GB — 이 서버 기록 기준). 최근 것과 last 만 남기고 지운다.

shell 창 — 최근 5개만 남기기
cd outputs/train/panda_runpod/checkpoints
ls -d [0-9]* | sort -n | head -n -5                  # 지울 목록을 먼저 본다 (last 가 가리키는 최신은 여기 없다)
ls -d [0-9]* | sort -n | head -n -5 | xargs rm -rf   # 지운다
cd /workspace/hil-serl-mujoco-franka

learner 가 저장하는 중(learner 창에 저장 로그가 흐르는 동안)에는 하지 않는다.

결과 내려받기 (내 PC 에서)

내 PC — 학습된 정책 (마지막 체크포인트)
scp -P <SSH_PORT> -i ~/.ssh/id_ed25519 -r \
  root@<POD_IP>:/workspace/hil-serl-mujoco-franka/outputs/train/panda_runpod/checkpoints/last/pretrained_model \
  ./panda_runpod_last

scp 는 대문자 -P 로 포트를 받는다. 기본 SSH(ssh.runpod.io)로는 안 된다.

완전히 끝낼 때

필요한 것을 내려받은 뒤 RunPod 화면에서 Terminate. 볼륨까지 지워지고 요금이 더 나가지 않는다. GitHub 토큰도 지운다.
