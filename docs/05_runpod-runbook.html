저장소 github.com/gguldong2/hil-serl_franca_panda_gpu-learner 는 공개다(2026-11-18 확인 — 토큰 없이 clone 됐다). 그래서 clone 에는 토큰이 필요 없다. pod 에서 고친 것을 GitHub 에 올릴(push) 때만 비밀번호 대신 토큰을 넣는다(16). 저장소를 다시 비공개로 돌리면 clone 때도 Username · Password(토큰)를 묻는다.

  • 저장소 주인 계정이면 — GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Repository access 는 Only select repositories → 이 저장소 하나, Repository permissions 의 Contents: Read and write(push 용. 비공개 저장소를 clone 만 할 거면 Read-only).

  • 토큰은 만들 때 한 번만 보인다. 메모해 두고, 끝나면 GitHub 에서 지운다(Expiration 을 짧게 잡아도 된다).

SSH 키 — 선택 (SSH 로 접속 · scp · 터널을 쓸 때만)

이 문서는 SSH 없이 끝까지 된다. 명령은 JupyterLab 터미널에서 치고, 대시보드는 RunPod 주소로 열고, 결과 파일도 JupyterLab 에서 내려받는다(03 · 16). SSH 를 쓰려면 pod 를 만들기 전에 키를 등록해 둔다 — 키는 pod 가 만들어질 때 들어간다.

내 PC — Windows PowerShell
if (!(Test-Path $env:USERPROFILE\.ssh\id_ed25519.pub)) { ssh-keygen -t ed25519 }   # 없으면 만든다. 묻는 것은 엔터
type $env:USERPROFILE\.ssh\id_ed25519.pub                                              # 나온 한 줄을 복사
내 PC — macOS · Linux
ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519     # 없으면 만든다. 묻는 것은 엔터
cat ~/.ssh/id_ed25519.pub                              # 나온 한 줄을 복사

RunPod 웹 → 계정 Settings → SSH Public Keys 칸에 그 한 줄을 붙여 넣고 저장한다.

붙여 넣는 것은 한 줄뿐 · ssh 를 칠 그 PC 의 키
  • ssh-ed25519 AAAA… 이름@컴퓨터 한 줄만 넣는다. ssh-keygen 이 그려 주는 +--[ED25519 256]--+ 그림까지 넣지 않는다(11-18 첫 pod 에 그림이 같이 들어가 있었다).
  • 키는 ssh 명령을 칠 PC 에서 만든 것이어야 한다. 다른 컴퓨터의 키만 등록돼 있으면 ssh 가 password: 를 묻는다 — RunPod 의 root 에는 비밀번호가 없어 무엇을 넣어도 안 된다(15).
  • 이미 만든 pod 에 키를 더하려면 pod 안에서 ~/.ssh/authorized_keys 에 한 줄을 붙인다(03).

RunPod 은 같은 GPU 를 두 경로로 빌려준다. Secure Cloud 는 RunPod 이 계약한 전문 데이터센터의 서버라 안정적이고 값이 높다. Community Cloud 는 RunPod 이 심사한 외부 개인 · 업체가 내놓은 서버라 싸지만, 서버마다 네트워크 · 공개 IP 유무 · 중간에 멈출 가능성이 다르다. Deploy 화면에서 둘 중 하나를 먼저 고르면 그쪽 재고와 값이 보인다. 이 문서에서 "$2.19 / $1.39" 처럼 쓴 것은 같은 GPU 의 시간당 Secure 값 / Community 값이다. 하루쯤 돌리는 학습이라 Secure 를 권하고, Community 를 고르면 pod 를 만든 뒤 Connect 탭에 "SSH over exposed TCP" 가 있는지 꼭 확인한다.

순서대로

버튼 이름은 RunPod 화면이 바뀌면 조금 다를 수 있다 추정. 칸의 뜻은 위 표와 같다.

  1. Pods → + Deploy. 맨 위에서 Secure Cloud 를 고른다.
  2. GPU 를 고른다 — 목록에서 L40S(또는 RTX A6000), GPU Count 1. 회색이거나 고를 수 없으면 "L40S 가 없을 때" 순서로. RTX 5090 · RTX PRO 6000 같은 Blackwell 이면 Additional filters → CUDA Version 을 12.8 이상으로(템플릿을 CUDA 12.8 로 고르면 저절로 맞는다).
  3. 템플릿 — Change Template → 공식 Runpod PyTorch. 버전을 고르는 칸이 있으면 CUDA 12.8 · Ubuntu 22.04, PyTorch 는 기본값. 이미지 이름이 runpod/pytorch:…-cu1281-torch…-ubuntu2204 꼴이면 맞다. 이 이미지 이름을 적어 둔다(04 T18). 이름이 "Ubuntu" 뿐인 템플릿은 JupyterLab 이 없을 수 있어 고르지 않는다.
  4. Edit Template(이 pod 에만 적용)을 눌러:
    • Container Disk 30 GB · Volume Disk 100 GB · Volume Mount Path /workspace
    • Expose HTTP Ports 에 8888 과 8088(쉼표로 구분 추정) · Expose TCP Ports 에 22 가 있는지
    • Environment Variables 에 NVIDIA_DRIVER_CAPABILITIES = all, JUPYTER_PASSWORD = 긴 비밀번호 추가
    • Set Overrides(저장)
  5. Pricing 은 On-Demand. "Start Jupyter Notebook" 같은 체크박스가 보이면 켠다 추정.
  6. Deploy On-Demand → 상태가 Running 이 될 때까지 기다린다(이미지를 받느라 몇 분).
  7. Connect 탭에서 확인한다: ① HTTP Services 의 Jupyter Lab(8888) 링크 — 명령은 여기 터미널에서 친다(03). ② HTTP Services 의 8088 — 대시보드를 띄우기 전까지 Initializing 이 정상이다. --host 0.0.0.0 으로 띄우면 Ready 가 된다(03). ③ (SSH 를 쓸 때) "SSH over exposed TCP" 명령(ssh root@IP -p 포트 …). 없으면 그 서버에 공개 IP 가 없는 것이다 추정.

템플릿 · CUDA 를 이렇게 고르는 이유

  • 템플릿의 PyTorch · CUDA 는 쓰지 않는다. 02 가 /workspace 의 프로젝트 venv 에 CUDA 런타임이 든 torch 2.11.0 을 따로 깐다. RunPod PyTorch 이미지에는 2.11 이 없고, 시스템에 깐 것은 pod 를 멈추면 지워진다(04 §07).
  • 템플릿의 CUDA 버전은 "그 버전을 지원하는 드라이버의 서버에만 뜬다" 는 조건으로만 작용한다. 12.8 이면 드라이버 570 이상 → cu126 · cu128 둘 다 된다. 12.9 · 13.x 도 되지만 고를 수 있는 서버가 좁아질 뿐 얻는 것이 없다 추정.
  • Ubuntu 22.04 는 기준 서버와 같다. 24.04 도 된다 — 2026-11-18 첫 pod(L40S)가 24.04 이미지였고 설치(00 ~ 03) · preflight 를 통과했다. 이 이미지에는 Python 3.12(venv · 헤더까지)가 이미 들어 있고 deadsnakes 저장소도 미리 등록돼 있어, 01 은 Python 단계를 건너뛴다(04 §06).
만든 뒤 설정을 바꾸면 — 8088 을 나중에 넣을 때도

Edit Pod 로 포트 · 환경변수 · 디스크를 바꿔 저장하면 pod 가 다시 시작되고 /workspace 밖이 지워진다(apt 로 깐 것 · tmux 세션 · 돌던 프로세스). 그 뒤에는 14 다시 켤 때와 같다. 8088 을 빠뜨렸으면 설치를 시작하기 전에 넣는 것이 가장 싸다 — 11-18 첫 pod 는 설치 전에 Edit Pod 로 8088 을 더했다.

L40S 가 없을 때 — 왜 없나 · 어디서 보나 · 대안 순위

GPU 를 고르는 단계에서 "쓸 수 있는 것이 없다" 고 나오면 거의 항상 그 GPU 종류가 지금 그 조건(클라우드 · 지역 · 필터)에서 다 빌려 간 상태다. 템플릿 때문이면 모습이 다르다 — GPU 는 고를 수 있고 pod 도 만들어지는데, 시작하다가 멈춘다.

원인어떻게 보이나확인 · 할 일
재고 없음 (가장 흔함)GPU 목록에서 그 카드가 회색이거나 고를 수 없다. 재고가 적다는 표시가 붙기도 한다 화면 문구 추정Secure ↔ Community 를 바꿔 보고, 지역(데이터센터) 필터를 전체로 둔다. 재고는 수시로 바뀌니 잠시 뒤 다시 본다. 그래도 없으면 아래 대안
필터가 좁힘위와 같다Additional filters 의 CUDA Version 은 12.8 로(더 높이면 고를 수 있는 서버가 준다), GPU Count 는 1. 네트워크 볼륨을 붙이면 그 볼륨이 있는 데이터센터의 서버만 고를 수 있다 — 이 절차는 네트워크 볼륨을 쓰지 않는다
템플릿의 CUDA 가 서버 드라이버보다 높음GPU 는 골라지고 pod 도 생기지만, 시작 로그에 unsatisfied condition: cuda>=X.X 가 나오며 뜨지 않는다템플릿을 CUDA 12.8 로 고르거나, Additional filters 의 CUDA Version 을 템플릿의 CUDA 이상으로(RunPod 문서의 안내)

정리: GPU 고르는 화면에서 막히면 재고 · 필터 문제, pod 가 만들어진 뒤 시작에서 막히면 템플릿(CUDA) 문제다. GPU 목록 자체가 가용 자원 화면이므로, 클라우드 · 지역을 바꿔 가며 그 GPU 카드가 고를 수 있게 바뀌는지 본다.

SSH — 선택 (scp · 터널)

내 PC — Connect 탭의 "SSH over exposed TCP" 명령. 터널이 필요하면 -L 을 붙인다
ssh -L 8088:localhost:8088 root@<POD_IP> -p <SSH_PORT> -i ~/.ssh/id_ed25519
  • -L 8088:localhost:8088 은 대시보드 터널이다. 이 SSH 창이 열려 있는 동안 내 PC 브라우저의 http://localhost:8088/ 이 pod 의 대시보드로 이어진다. 내 PC 의 8088 을 다른 프로그램(VS Code 포트 포워딩 등)이 이미 쓰고 있으면 -L 18088:localhost:8088 으로 바꾸고 http://localhost:18088/.
  • "SSH" 칸의 …@ssh.runpod.io 명령(기본 SSH)은 쓰지 않는다. 그쪽은 파일 전송(scp)이 안 되고 터널도 기대할 수 없다.
  • 처음 접속하면 Are you sure you want to continue connecting 에 yes.
  • root@…'s password: 를 물으면 이 PC 의 키가 pod 에 없는 것이다. Identity file … not accessible 이 같이 나오면 PC 에 키 파일부터 없다 → 01 에서 키를 만든다.
pod 안(JupyterLab 터미널) — 이미 만든 pod 에 내 PC 키 더하기. 바로 된다
echo 'ssh-ed25519 AAAA…(내 PC 의 id_ed25519.pub 한 줄)' >> ~/.ssh/authorized_keys

~/.ssh 는 /workspace 밖이라 pod 를 다시 켜면 이렇게 더한 키는 지워진다. 다음 pod 를 위해 RunPod Settings 의 SSH Public Keys 에도 넣는다(01). 이미 있는 pod 가 다시 켤 때 Settings 의 새 키를 받는지는 추정 — 안 되면 위 한 줄을 다시 친다.

개입 — UR5e 실측에서 나온 요령

  • Space 로 조종권을 잡으면 빨간 테두리와 ● 개입 중 (REC) 가 뜨고, 다시 Space 로 정책에 돌려준다. Esc 는 이 판을 실패로 넘긴다. 조작 키는 08 과 같다.
  • 정책 혼자 성공하는 판이 나오기 전에는 개입을 끊지 않는다. 처음에는 무작위 정책이라 헤맨다. 개입 없이 기다리면 수백 판이 0% 로 간다.
  • 판을 통째로 대신 하기보다 막히는 지점에서만 짧게 잡아 주고 놓는다.
  • 혼자 성공률이 50% 를 넘어 유지되면 개입을 멈춘다. 그 뒤로는 정책이 스스로 나아진다. 근거: 03 Q6 · 06 §03.
  • 학습 중 화면에는 내 조작이 섞여 있어 정책 실력이 아니다. 실력은 11 의 추론으로 본다.

pod 에서 고친 것을 GitHub 에 올리기 (push)

커밋에 찍힐 이름 · 이메일을 정하고, push 할 때 비밀번호 칸에 토큰(01)을 넣는다. --global 은 ~/.gitconfig 에 적는데, 이것은 /workspace 밖이라 pod 를 멈추면 지워진다. 프로젝트 폴더 안에서 --global 없이 적으면 .git/config 에 들어가 pod 를 다시 켜도 남는다.

shell 창 — 처음 한 번 (프로젝트 폴더 안에서)
git config user.name  "gguldong2"
git config user.email "<GitHub 계정 이메일>"        # 커밋 작성자로 찍힌다. 감추려면 Settings → Emails 의 …@users.noreply.github.com
git config credential.helper 'cache --timeout=28800'   # 토큰을 메모리에 8시간 기억. 디스크에 남지 않는다
git config -l | grep -E '^(user|credential)\.'         # 확인
shell 창 — 올릴 때마다
git status                          # 무엇이 바뀌었나
git add <파일들>
git commit -m "무엇을 왜 바꿨나"
git pull --rebase                   # 그사이 다른 곳에서 올린 것이 있으면 먼저 받아 그 위에 얹는다
git push                            # Username: gguldong2 · Password: 토큰 (붙여 넣어도 화면에 안 보이는 게 정상)
