  1. 실험 만들기설정 파일 하나를 베낀다. 이름당 딱 한 번
  2. tmux 칸마다 export CFG칸을 새로 열거나 다시 붙을 때마다

  4. 개입하며 지켜보기정책 혼자 성공하기 전에는 개입을 끊지 않는다

이 문서에서 "스텝"
  • 최적화 스텝 — learner 가 신경망 가중치를 한 번 고친 것. 체크포인트 이름(002000), "2,000 스텝마다", 대시보드 가로축이 이것이다. 버퍼에서 배치 2개(각 256 = 온라인 128 + 오프라인 128)를 꺼내 크리틱을 두 번, 액터 · 온도를 한 번 고친다. 평균 초당 약 3.2회, 버퍼가 찬 뒤에는 저장 시간 때문에 실효 약 1.9회(03 문서 Q16).
  • 상호작용 스텝 — actor 가 시뮬레이터를 1/20초 움직인 것. 전이 하나가 생긴다. online_steps 1,000,000 이 이것이다.

무엇을 고치는지 · 왜 HIL-SERL 고유 개념이 아닌지는 03 문서 Q5, 두 스텝의 관계는 Q1 · Q2.

베낄 설정 파일이 없다면

4 · 개입

대시보드의 시뮬레이터 화면을 한 번 클릭해 테두리가 초록색이 되면 그 창의 키가 로봇으로 간다. Space 로 조종권을 잡고 놓는다. 키 배치는 런북 02 키보드.

개입 요령 — 실측에서 나온 것
  • 처음에는 무작위 정책이라 헤맨다. 정책 혼자 성공하는 판이 나오기 전에는 개입을 끊지 않는다. 개입 없이 기다리면 수백 판이 0% 로 간다.
  • 판을 통째로 대신 하기보다 막히는 지점에서만 짧게 잡아 주고 놓는다.
  • 혼자 성공률이 50% 를 넘어 유지되면 개입을 멈춘다. 그 뒤로는 정책이 스스로 나아진다.

원칙 — learner 와 actor 는 같이 끄고 같이 켠다
  • learner 만 남으면 새 데이터 없이 같은 버퍼로 계속 학습한다. 몇 분은 괜찮지만 몇 시간이면 정책이 망가지고 체크포인트가 쌓인다 (03 문서 Q9 · Q20).
  • actor 만 남으면 시뮬레이터는 계속 도는데 데이터를 보낼 곳이 없다. learner 가 꺼진 뒤의 판은 버려지고, learner 를 다시 띄워도 그 actor 는 다시 붙지 않는다 — actor 도 다시 띄운다.
  • learner 가 돌고 있는 칸(칸2)에는 명령을 칠 수 없다. stop · save · pause 는 export CFG 를 해 둔 다른 칸(칸4)에서 친다. 칸2 에서 할 수 있는 건 Ctrl+C(강제 종료)뿐이다.
