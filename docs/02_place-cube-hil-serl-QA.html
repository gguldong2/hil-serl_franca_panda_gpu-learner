사람의 개입

개입 없이 시연 데이터만으로도 결국 되지 않나

시간만 더 걸리는 게 아니다. 0% 에 머물 수 있다.

매 배치 256개 중 128개가 시연 버퍼에서 나오므로, 크리틱은 "시연이 지나간 상태는 가치가 높다"를 배운다. 문제는 정책이 실제로 도달하는 상태가 시연 상태와 멀 때다. 가치는 실제로 존재하는 전이를 따라서만 뒤로 전파되는데(벨만 백업), 온라인 전이가 전부 보상 0이면 정책이 있는 영역 안으로 가치가 흘러들어올 통로가 없다.

크리틱은 "내가 가는 곳은 전부 0, 저쪽 어딘가는 1" 로 나뉜 채 멈춘다. offline→online RL 의 고전적 실패 모드이고, RLPD 의 5:5 혼합이 완화하지만 없애지는 못한다.

초반 30판만 성공시키고 손 떼면 되나

계획은 타당하다. 다만 논문은 반대 방향을 경고한다.

"처음에 몰아서 도와주고 뒤는 맡긴다"는 합리적인 전략이고, 실제로 그렇게 해봤다. 결과는 51판까지 개입으로 성공시킨 뒤 398판 동안 성공 0이었다.

we should avoid persistently providing long sparse interventions that lead to task successes. Such an intervention strategy will cause the overestimation of the value function, particularly in the early stages of the training process; which can result in unstable training dynamics.

HIL-SERL (Luo et al., 2024)

"처음부터 끝까지 대신해서 성공시키기"가 정확히 이 경우다. 크리틱은 그 경로의 가치를 높게 잡는데 정책은 그것을 재현할 능력이 없다. 부풀려진 값을 교정할 기회가 필요한데, 개입을 0으로 끊으면 그 기회가 사라진다.

성공 보상이 생기면 그걸 위주로 업데이트되나

아니다. advantage 도, 정책 채택 판정도, 우선 샘플링도 없다.

흔한 오해실제 SAC
advantage 로 비교없음. A = Q − V 는 PPO·A2C 계열
기존 정책보다 나으면 채택없음. 채택/거부 판정이 아예 없다
정책이 A→B 로 교체없음. 매 스텝 경사로 덮어쓴다
성공 데이터를 더 자주 뽑음없음. torch.randint 균등 샘플링

바뀌는 것은 신경망 가중치뿐이고, 버퍼의 데이터는 읽기만 한다. 손실 두 개가 전부다.

# 크리틱 — 성공 보상이 여기로 들어온다
td_target   = reward + (1 - done) * γ * [ min Q_target(s',a') − α·log π(a'|s') ]
loss_critic = MSE( Q(s,a), td_target )          # γ = 0.995

# 액터 — 크리틱이 좋다는 쪽으로 밀린다
loss_actor  = ( α·log π(a|s) − min Q(s, a_π) ).mean()

성공 하나는 한 번에 퍼지지 않고 뒤로 한 칸씩 간다.

성공한 판:  s₀ → s₁ → … → s₇₉₈ → s₇₉₉ (성공, r=1.0)

1회차 갱신   Q(s₇₉₉) → 1.0
2회차        Q(s₇₉₈) → γ·1.0   = 0.995      (타깃이 s₇₉₉ 의 Q 를 참조)
3회차        Q(s₇₉₇) → γ²·1.0  = 0.990
…            판 시작까지 닿으려면 그 전이가 배치에 여러 번 뽑혀야 한다

"성공 위주"에 가장 가까운 장치는 우선순위가 아니라 버퍼 배정 비율이다. 개입 전이는 온라인 버퍼와 시연 버퍼 양쪽에 들어가고, 시연 버퍼는 매 배치의 절반을 차지하므로 온라인 전이 하나보다 훨씬 자주 뽑힌다.

데이터가 흐르는 길

시연·개입·롤아웃 데이터는 각각 어디에 저장되고 어떻게 섞이나

저장 단위는 에피소드가 아니라 프레임 한 장. 개입 데이터만 양쪽 버퍼에 복사된다.

버퍼는 에피소드를 모른다. capacity 길이의 평평한 배열이고 한 칸이 (state, action, reward, next_state, done, truncated, complementary_info) 하나다. 에피소드 경계는 done 플래그로만 표시되고, 샘플링할 때 에피소드를 통째로 뽑는 일은 없다. 

# buffer.py:231 — 링버퍼. 꽉 차면 0번 칸부터 덮어쓴다.
self.position = (self.position + 1) % self.capacity
self.size     = min(self.size + 1, self.capacity)

데이터 종류를 가르는 라벨은 complementary_info["is_intervention"] 불리언 하나뿐이다. 그리고 그 라벨이 하는 일은 단 하나 — 개입 전이를 버퍼 두 곳에 모두 넣는 것이다.

replay_buffer.add(**transition)            # 모든 전이는 온라인 버퍼로

시연 버퍼도 링버퍼다. 그리고 최적화 스텝 210,010 에서 40,000칸이 꽉 찼다. 쓰기 위치가 0번으로 되감겼고, 0번 칸부터는 원본 시연이 들어 있다.

이제 새 개입 프레임 1개가 들어올 때마다 가장 오래된 시연 프레임 1개가 사라진다. 

시연 버퍼 40,000칸

  [19,612 .. 39,999 ]  ← 그 뒤 쌓인 개입 20,388 프레임
  → 가득 참. position 이 0 으로 되감김.
  → 새 개입 1프레임 = 시연 1프레임 소멸

학습은 언제, 어떤 단위로 일어나고 얼마나 걸리나

에피소드와 무관하게, 쉬지 않고, 초당 2.74번.

learner 는 에피소드가 끝나기를 기다리지 않는다. actor 가 스텝을 흘려보내는 동안 독립적으로 while True 를 돈다. 

# learner.py:410 — 메인 루프
while True:
    process_transitions(...)              # actor 가 보낸 전이 수신
    process_interaction_messages(...)
    if len(replay_buffer) < online_step_before_learning:   # 100
        continue
    stats = trainer.training_step()       # ← 1 optimization step
1 optimization step 에서 정확히 일어나는 일 — utd_ratio = 1 이므로 배치 1개
순서대상내용
1크리틱 앙상블 (2개)배치 256 으로 벨만 회귀 · grad clip · step
2discrete critic그리퍼 3-way (num_discrete_actions: 3)
3액터policy_update_freq = 1 → 매 스텝
4온도 α엔트로피 목표 맞추기
5타깃 네트워크soft update, τ = 0.005

배치를 뽑는 곳이 next(batch_iterator) 한 줄이다. 즉 5:5 혼합은 "주기적"이 아니라 매 배치 — 초당 2.74회 일어난다.
